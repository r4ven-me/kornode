# Decisions and spikes

Format: ID, decision, rationale, status. `spike` entries are assumptions to
verify early in the named phase with a throwaway test; if a spike fails, apply
the listed fallback and update this file and the affected spec.

## Taken

| ID | Decision | Rationale |
| --- | --- | --- |
| D-01 | Inter-node transport: ocserv/openconnect, 443/tcp, DTLS optional. | Owner requirement: traverses restrictive networks, single port. |
| D-02 | Topology: hub-and-spoke. No agent-to-agent tunnels. | Matches the transport (agents dial the hub), simplest correct routing. |
| D-03 | WireGuard only as a third-party access server attached as a `source`. | Owner requirement. |
| D-04 | Control plane is pull-only over the fabric; enrollment also goes through ocserv (one-time `enroll` user). | No inbound ports on agents, no second public port on the hub, works behind DPI exactly like the fabric. |
| D-05 | Registry in SQLite (WAL); hub's own settings stay in YAML. | Registry is mutable inventory, not configuration; YAML-first stays for settings. |
| D-06 | Bundles are signed with Ed25519 (detached signature over exact bytes), separate from TLS. | Cached bundle stays verifiable at boot without the hub. |
| D-07 | Apply-with-confirm: 60 s health window, automatic rollback. | A bad bundle must not strand an agent. |
| D-08 | Bundles never expire. Only the agent certificate does (90 days, renew at 2/3). | Hub outage must not become a network outage. |
| D-09 | Agent is Python, same repo, separate package and image; depends on `kornode.net`, `pydantic`, `httpx`, `pyroute2`, `cryptography`. No FastAPI, no frontend. | Reuse of the data-plane core; one language for the team. |
| D-10 | Egress rules: ordered, first match wins. | Removes "last mark wins" ambiguity. |
| D-11 | Kill switch at two layers: `unreachable` route in each exit table + nft `oifname` check. | No leak window during tunnel bounce. |
| D-12 | Netlink via pyroute2 instead of parsing `ip -j`. | Atomicity, events, no text parsing. |
| D-13 | Hub-only capabilities follow CLI ⇄ API ⇄ Web parity, enforced by `parity.yaml`. | Owner requirement. |
| D-14 | Agent has no web panel; local CLI only. Remote diagnostics through hub commands. | Minimal attack surface and code size. |
| D-15 | Per-node addressing derived from `node.id` (1–254). Hub is node 1. | Prevents overlap by construction. |
| D-16 | Secrets for agents are sealed per agent: ephemeral X25519 + HKDF-SHA256 + ChaCha20-Poly1305. | Bundle bodies may be logged/cached; secrets stay unreadable to other agents. |
| D-17 | P0's `rp_filter=2` is set unconditionally on `all`/`default`/tunnel ifaces, not the "2 if currently 1, else unchanged" nuance in `03-kernel-dataplane.md`. | That nuance is P2's `kornode.net` kernel module's job; P0 only patches the existing services on the current codebase (ROADMAP's own scoping), not the new core. |
| D-18 | `korctl doctor` is a new, separate command/service from `korctl diagnose`/`DiagnosticsService`, not merged into it. | Different purpose (network-sanity assertions vs. raw software/interface info dumps); avoids changing `diagnose`'s existing contract. |
| D-19 | P0 is verified by unit tests (`FakeRunner`/golden-template pattern) only; the ROADMAP P0 "Done when" criteria that call for netlab evidence are left unverified until P1's `tests/netlab/` framework exists. | P1 (the netlab harness) was out of scope for the P0 implementation session; conservative choice was to ship P0 on the existing unit-test convention rather than block on building P1 first.  **Superseded 2026-10-12:** P1 netlab now verifies P0 for real (see D-20, D-21, `docs/spec/09-testing.md`); only the 50 MB nested-tunnel MTU criterion is still uncovered. |
| D-20 | Carrier addresses are exempted from nft marking (`ip daddr { ... } return` at the top of the output chain), not only via `ip rule priority 95`. `install_carrier_exclusion` runs before the nft apply in `connect()` so the renderer sees the recorded addresses. | Found by netlab (P1-03): under `host_policy: full` the carrier SYNs were marked, rule 95 sent them via main, and the postrouting kill-switch dropped them -- the tunnel could never come up. |
| D-21 | Kill-switches (client `forward` and host `postrouting`) drop marked traffic leaving via the **uplink** (main table's default-route interface, resolved like `NetworkStatsService.resolve_interface()`), not "any interface but the tunnel". If the uplink can't be resolved, the strict `oifname != <tunnel>` form is rendered (fail closed). Owner decision 2026-10-12. | P0-03's `suppress_prefixlength 0` correctly sends marked traffic for connected LAN/docker/client networks via main, but the old kill-switch dropped it (marked, oif != tunnel) -- ROADMAP P0 "Done when" could not hold. After P0-03/P0-04 a marked packet only leaves via a non-tunnel interface through a specific main route; the internet leak path is the uplink, which stays blocked. Trade-off: hosts on the uplink's own subnet are unreachable for marked traffic. Verified in netlab (`test_suppress_rule_keeps_connected_routes_ahead_of_policy_table`). |
| D-22 | nft scripts generated by `kornode.net` never inline set elements (enforced by `NftRuleset`); elements are always applied separately. The schema hash is the SHA-256 of the script, and the kernel adapter tracks the hash of what it last loaded. | Element churn (domain resolution, list refresh) must never force a full table reload (spec 04), and comparing our own script hash is deterministic, unlike parsing `nft list` output back. |
| D-23 | Route identity in `kornode.net` is (family, table, destination, metric); everything else about a route with the same identity is a replace. | Matches kernel semantics for `ip route replace`, and lets an exit's `default dev <tun>` and its `unreachable default metric 4096` coexist in one table (spec 03). |
| D-24 | One table, one kill-switch per exit: an exit fails closed (`unreachable`) if any rule using it has `kill_switch: true`; only when all its rules opt out does it get `throw`. | The kernel layout has one table per exit (spec 03), so per-rule fall-through cannot be expressed; failing closed is the conservative choice. |
| D-25 | Compiled nft sets hold exactly config routes + addresses the resolver reports in `NodeFacts.resolved`; no element timeouts. The resolver feeds facts and wakes the reconciler instead of writing to nft. | Deterministic set contents and a single writer (spec 04: only kornode.net touches the kernel); spec 02's timeout scheme existed to avoid two writers racing. |
| D-26 | Unmarked client/source traffic leaving towards this node's own connected networks is masqueraded (`ip saddr <pool> ... meta mark == 0 masquerade`). | v1 behaviour: LAN/docker hosts have no route back to VPN pools. Fabric/exit traffic is marked and never hits this rule, so "no NAT inside the fabric" holds. |
| D-27 | Implicit rules 1-3 are also enforced at the nft layer: local addresses (`fib daddr type local`), this node's connected networks/pool/source subnets (`@local_*`) and tunnel carriers (`@carrier_*`) are returned before classification and never marked. Only kornode's own ct marks (`0x0c......`) are restored. | Belt and braces with rule 90/95 (and D-20/D-21): local and carrier traffic can never be caught by a kill-switch, and foreign conntrack marks are never imported. |
| D-28 | Kill-switch action: `reject with icmpx admin-prohibited` in `forward`, `drop` in `postrouting` (host traffic). Spec 03 updated. | The kernel refuses `reject` in postrouting ("Operation not supported"); `nft -c` does not catch it, a real load did (netlab). Golden rulesets are now loaded into a real kernel in netlab, not only syntax-checked. |
| D-29 | **No backwards compatibility** with v1 deployments (owner decision 2026-10-12): no in-place upgrade path, no auto-migration of a running node's kernel state, no dual-run of old and new routing code. P2's hub cut-over replaces the v1 services outright (`NftablesService`, `PolicyRoutingService`, kernel calls in `UpstreamService`, `nftables*.j2`) and a node is reinstalled/restarted clean. v1 *config keys* stay as the hub's input until P5 (translated by `kornode.config.legacy`) -- that is input format, not runtime compatibility. | Compat shims were the largest cost driver (`remove_v1_state`, dual ownership of the same kernel ranges). Supersedes the P2 plan's "one-shot v1 cleanup" risk item. |
| D-30 | The reconciler control socket has a synchronous `apply` op (one pass inside the request, replies with the status); `NetService.apply` uses it, `NetService.converge` raises on `last_error`, `NetService.wake` (async) is only for hooks and the resolver. `UpstreamService.connect` converges before the dial and after the tunnel is up. | `wake` returns before the pass ran, so it cannot guarantee the kill-switch precedes the dial (D-20) or report a failed pass (the v1 "connect ignores a failed nft apply" bug). |
| D-31 | The runtime-switched active profile (`generated_dir/active-upstream`) is a reconciler input: `HubNetInputs.policy()` passes `selected_profile(config, files)` to `legacy_policy`, which falls back to the config's selection only when no override is given. | `switch_profile` previously re-pointed nft/routes itself; with a single writer the reconciler has to see the switch or it would revert it on the next pass. |
| D-32 | Stale kornode marks never leave via the uplink: forward/postrouting reject/drop any `0x0c......` mark that is not a current exit's toward the uplink (any interface when the uplink is unknown). Marks stay index-based. | Established flows keep the ct mark of an exit that a policy change removed; that mark has no ip rule and no kill-switch, so it fell through to main and left un-NATed via the uplink (code review of P2). Stable per-name marks would not help with removed exits; breaking those flows is the fail-closed outcome. |
| D-33 | `Kernel.apply` does not stop at the first failed op: additive ops (sysctl, routes, rules, nft) still run, deletions after a failure are skipped, all failures are raised together. The reconciler treats any exception in a pass as an errored pass. The ocserv connect hook uses `converge` (reports a failed pass). | A failed sysctl or a vanished tunnel aborted the pass before the rules and the nft kill-switch on every pass (fail open on a cold start); a `NetlinkError` on read or a YAML error killed the reconciler loop (code review of P2). |
| D-34 | Bundle code (models, canonical encoding, sign/verify, seal/unseal, validator) lives in a shared package `kornode.bundle` (stdlib, `pydantic`, `cryptography`, `kornode.net` only; AST import test). `cryptography` becomes a runtime dependency of hub and agent. | Hub compiler and agent must run the very same validator; keeping crypto out of `kornode.net` leaves the data-plane core dependency-free. |
| D-35 | Ed25519 signs `b"kornode.bundle.v1\0" + body`; envelope `ed25519:<key_id>:<b64>` with `key_id` = 16 hex of sha256(pubkey). In `/poll` and the enroll result the body is base64 (`body_b64`), never an embedded JSON object. The agent never re-encodes a body. | Domain separation for the signing key; key ids make rotation explicit; an embedded object would be re-serialized and break the exact-bytes signature. |
| D-36 | Sealing per value: ephemeral X25519, HKDF-SHA256 with `salt = epk ‖ seal_pubkey`, `info = aad = "kornode-bundle-secret-v1\|<node_id>\|<JSON pointer>"`, ChaCha20-Poly1305 with a random 12-byte nonce. | Implements D-16; binding the field path stops ciphertexts being moved between fields. |
| D-37 | Next version = `max(latest, desired_version, high_water_version) + 1`; dedup by `content_hash` (canonical body minus `version`/`generated_at`, sealed values replaced by HMAC(master key, info ‖ plaintext)). The agent keeps `high_water` (highest verified version) and polls with `since=high_water`; the hub stores it and recompiles above it. Replaces the 409 round-trip on reports. | Randomized sealing makes byte comparison useless; HMAC avoids hashing low-entropy secrets in the clear. Monotonicity after a hub restore needs no special error path. |
| D-38 | Bundles are compiled synchronously inside the registry transaction of every relevant mutation (plus YAML save and control API start); no queue, no debounce. The compiler runs the agent validator on its own output and refuses to store an invalid bundle. Long-poll waiters re-check `desired_version` every 500 ms. | One writer path, `desired_version` can never point at a missing bundle, and cross-process notification needs nothing beyond SQLite. Fan-out ≤ 253 small documents. |
| D-39 | Agent state: `state.json` is the only pointer (no `current` symlink); a restart inside a confirm window always rolls back; the bootstrap state (`current = 0`, fabric only, empty egress) is the fallback when nothing verifies or the first bundle fails. | Conservative: a crash during the window may be the bundle's fault; the bootstrap state keeps the path to the hub without marking any traffic, so nothing can leak. |
| D-40 | Health checks are "no regression": `fabric` (mTLS `GET /agent/v1/ping`) is always required; an upstream exit is required only if it is new in the bundle or passed in the pre-apply baseline. After a rollback a 30 s fabric check assigns blame: healthy → `failed` (never retried), still down → `deferred` (retried when fabric is back, max 3). | Spec 06 required every upstream to be up, so a pre-existing outage would roll back every unrelated change; and a hub outage during the window must not permanently blacklist a good bundle. |
| D-41 | Registry migrations are forward-only SQL files keyed by `PRAGMA user_version`; a newer DB than the code is refused (no downgrade). Snapshots: hourly check, 24 h cadence, keep 7, in `data_dir/backups/registry/`, integrity-checked; retention is a constant, not config. | Avoids silent downgrade/corruption and keeps the P3-01 storage layer simple; no GUI field is needed until P3-09 makes hub backup configurable. |
| D-42 | The `enroll` group leases from a dedicated `fabric.enroll_pool` (default `10.99.255.240/28`) outside `fabric.cidr`, validated by the overlap validator. | spec 07's `10.99.0.240/28` collided with the fabric addresses of nodes 240–254, and leases inside `fabric.cidr` would match the hub's `from: fabric` transit rules. A separate pool also makes S-04's fallback a static rule set. |
| D-43 | Clients and agents share one listener via alternative auth: `auth = "plain[...]"` + `enable-auth = "certificate"`, `cert-group-oid = 2.5.4.11`. With `fabric.enabled` the hub connect-script refuses a session whose `GROUPNAME` is empty, and an `agents` session whose user is not `agent-<id>`; password users without a group get `clients`; usernames `agent-*`/`enroll-*` and groups `agents`/`enroll` are reserved; `auth.certificate.enabled` (client cert + password) is rejected together with `fabric.enabled`. | S-01 netlab: with `enable-auth` any certificate of the hub CA logs in **without a password** (an OU-less client cert got a session in the default group); the guard refuses it. Client cert + password cannot be expressed next to cert-only agents, so the combination fails closed instead of silently becoming cert-only. |
| D-44 | The `enroll` restriction is a static nft rule set compiled by `kornode.net` (enroll pool → only `tcp <hub fabric addr>:<control.port>` in `input`, dropped in `forward` both ways); ocserv `restrict-user-to-routes`/`restrict-user-to-ports` are not used. | S-04 netlab: ocserv implements them by running `/usr/libexec/ocserv-fw` (iptables) — a second kernel writer, and a silent no-op where `iptables` is absent (enroll session reached `:22`, hub LAN and the internet). |
| D-45 | The hub signs only the **public key** of an agent CSR (`certtool --load-pubkey`), never the CSR: the subject comes from the hub template (CN=`agent-<id>`, OU=`agents`), proof of possession and ECDSA P-256 are checked in Python (`cryptography`, now a runtime dependency). Issued certificates are kept as `certs/agents/agent-<id>-<serial>.crt` so a revocation covers every live one; renewal does not revoke the previous certificate. The enroll token id doubles as the suffix of the ocpasswd user (`enroll-<node>-<id>`), `cert_lifetime_days` is the constant 90 until P3-05 adds `control.*` config. | `certtool --load-request` copies the subject from the attacker-controlled CSR (CN/OU `agents` forgery); keeping all PEMs is the only way to put an old-but-live certificate on the CRL. |
| D-46 | P3-03 is the service layer only: `EnrollmentService` (issue/revoke token, enroll, renew, revoke node, maintenance) with typed `EnrollmentError(status, code)`. HTTP wiring, mTLS, binding to the hub fabric address and the 5/min rate limit are P3-05; `korctl agent`, `/api/agents/*`, the panel and `parity.yaml` rows are P3-08 (the only new CLI entry, `registry maintain`, is a supervisor entrypoint exempt like `registry snapshot`). | A capability is not added without all three interfaces (parity rule); the Control API process does not exist yet. |
| D-47 | The hub drops, in `prerouting` before classification, any packet from an ocserv session device (`<server.device>*`) whose source is not routed back through that device (`iifname "vpns*" fib saddr . iif oif missing drop`). The agent's connect-script guard additionally requires `config-per-user/agent-<id>`, and `ocserv.conf` carries `crl`; a revoked/removed agent is refused even with a stale CRL, and its live session is cut with `occtl disconnect`. | netlab: an enroll session forging the address of a live agent passed the `ip saddr <pool>` enroll rules (2 packets to `input`, 4 to `forward`); the kernel's loose `rp_filter=2` (required by tunnels, D-32) only drops sources with no route at all. Strict RPF is scoped to ocserv sessions and IPv4 (`meta nfproto ipv4`, so link-local IPv6/NDP is untouched), so tunnel devices keep `rp_filter=2`. `fib` ignores fwmark rules: return routes of sessions must live in `main` (the fabric's host routes do). |
| D-48 | P3-04 compiler choices left open by D-34..D-38: (1) the hub master key (HMAC for `content_hash`, encryption of `externals.secrets`) is 32 random bytes in `data_dir/control/master.key` (0600, created on first use, next to `signing.ed25519`); (2) the hub validates its own output without unsealing (only the agent holds the X25519 private key), so step 4 of the validator is structural on the hub; (3) the compiler prepends a `to-fabric` rule when the node policy has no `via: fabric` rule, so a bundle never cuts the path to the hub; (4) `access`, `dns` sections are not emitted until P4-04/P4-03; (5) revocation recompiles other agents *after* the revoke transaction, as a reported late step: a refused bundle must never block a revocation. | Master key and unsealing follow from the trust model; (3) keeps spec 11 true even for a hand-written policy; (5) fails closed on the security-relevant action. | `BUNDLE_HISTORY=20`, `MIN_AGENT_VERSION=2.0.0` and the `oc-hub0` interface name are constants until P3-05 adds `control.*`. |
| D-49 | Control API TLS: one listener (`control.port` on the hub fabric address) with `ssl_cert_reqs=CERT_OPTIONAL` and the kornode CA, so a presented client certificate must chain to the CA but `POST /agent/v1/enroll` still works without one. uvicorn does not expose the peer certificate, so `PeerCertProtocol` (an `H11Protocol` subclass, started from `python -m kornode.control` because the CLI cannot select it) stores the verified DER in the per-connection state; `MutualTLSMiddleware` requires it on every route but enroll and checks CN `agent-<id>` **and** OU `agents`, the CRL (`certs/crl.pem`, re-read on mtime change, signature checked against the CA, missing/invalid/stale list = 503, fail closed) and `nodes.state`. The listener has its own server certificate `certs/control.crt` (ECC, IP SAN = hub fabric address, 825 d, reissued under 30 d left). | Spec 05 said `CERT_REQUIRED`, which cannot coexist with enroll on one port; a second port would change D-44's nft rules. Defence in depth against fail-open: a test hits every route without a certificate (401), and the OU check keeps a user certificate with a forged CN out. |
| D-50 | The hub fabric address `10.99.0.1/32` is bound to `lo` by the reconciler (`NodeFacts.service_address`, only on node 1 with `control.enabled`; new add-only `Address` primitive in `kornode.net`, never removed because kornode cannot prove it owns a foreign address). `control-api` is started by supervisor with `startretries=100`, so it follows the reconciler. | `lo` keeps the address independent of any link; "only `kornode.net` touches the kernel" stays true. |
| D-51 | `EnrollmentService.enroll(end_session=False)` leaves the enroll VPN session up; the Control API ends it (`end_enroll_session`) in a background task 5 s after the answer was sent. The ocpasswd entry is still removed inside `enroll`. | netlab: `occtl disconnect` inside `enroll` cut the tunnel carrying the answer, so the agent never got its certificate while the token was spent and the node `active`. Known limit: if the answer is lost anyway, the operator revokes and re-creates the node. |
| D-52 | Control API limits and recovery: `since`/versions are clamped to 0…2^31-1 (400 otherwise); `high_water_version` only grows; `since` above the hub's latest recompiles with `force=True` (skips content dedup, otherwise the agent would get a version it must reject as a replay); report ≤ 256 KiB, command result ≤ 8 MiB, enroll/renew ≤ 64 KiB; a report with another `node_id` is refused (identity is the certificate); a node may finish only its own delivered command; enroll attempts (all of them) are limited to 5/min per source in process; every authenticated request refreshes `last_seen`; `control.min_agent_version` and `control.bundle_history` replace the P3-04 constants. | Authenticated agents are still untrusted for sizes and versions (spec 11); the rest closes the loose ends of D-37/D-45/D-48. |
| D-53 | Agent packaging and enroll: the openconnect dialing pieces (`DialSpec`, argv builder, carrier resolution, certificate pin, the interface-only `vpnc-script-kornode`) live in `kornode.tunnels`, stdlib only (AST-checked); `UpstreamService` calls them, process lifecycle stays per side. `kornode_agent` may import only `kornode.net/bundle/tunnels`, httpx, cryptography, pydantic, yaml, and is covered by the single-kernel-writer scan. The enroll token gained `control` (the control API URL on the hub fabric address) so the agent need not guess it; the enroll request itself is sent with TLS verification off because the agent has no CA yet, inside the enroll openconnect session whose server certificate is pinned; the CA arrives in the response and is the only trust anchor afterwards. The enroll bundle is verified but not cached: the run loop's first `poll(since=0)` fetches and applies it. `validate(..., revalidate=True)` skips only the replay check, for cached bundles. | Keeps one dialer without making the agent depend on hub config; a spec-05 token without the control URL would have forced a hard-coded fabric address. A single apply path avoids a second "first bundle" code path. |
