## P1 — до production

### A01. HTTP Basic полностью обходит административный TOTP

**Код:** `backend/kornode/api/auth.py:137–159`,
`backend/kornode/api/routes_auth.py:29–62`.

Второй фактор проверяет только login endpoint. `require_admin()` принимает те же
username/password через Basic без TOTP и даёт доступ к защищённым действиям,
включая `/api/auth/totp/disable`.

**Проверка:** TestClient с синтетическими credentials: login без OTP → 401;
Basic GET config → 200; Basic disable TOTP → 200, настройка выключена.
Атакующему нужен пароль; анонимного обхода не установлено.

**Исправление:** при включённом TOTP запретить password-only Basic для admin API.
Для автоматизации, если нужна, определить отдельные явные credentials/scopes.
MFA changes должны требовать надлежащую повторную аутентификацию.

**Acceptance:** Basic с правильным паролем не читает config и не выключает MFA
при включённом TOTP. Пересмотреть
`tests/test_admin_totp_api.py:97–110`: сейчас тест закрепляет обход.

### A02. Routing mark переиспользуется другим exit при изменении policy

**Код:** `backend/kornode/net/compile.py:126–132,298–315`,
`backend/kornode/net/nftgen.py:86–96,176–193`.

Marks/tables определяются порядком появления exit. Established connections
восстанавливают старый `ct mark` и не классифицируются заново. После удаления
первого upstream-rule прежний VPN mark может достаться `local`. VPN rule/table
исчезают, а stale-mark guard пропускает этот mark как всё ещё действующий.

**Проверка:** compiler/state-model repro: `upstream:primary / 0x0c000100` сменяется
на `local / 0x0c000100`; policy rule для VPN удалён, local не имеет kill-switch.
Это нарушает заявленную защиту established flows из `docs/spec/03-kernel-dataplane.md`.

**Impact:** созданы условия для выхода пакетов прежнего VPN-потока через обычный
uplink или другой exit. Успешная доставка прежнего TCP/NAT-потока не доказана;
это не исключает утечки пакетов на провод. Kernel capture не выполнялся.

**Исправление:** стабильное соответствие identity exit → mark/table, включая
lifecycle после удаления и restart. Не переиспользовать освобождённые marks,
пока существуют связанные conntrack entries, либо явно инвалидировать их.

**Acceptance:** netlab established flow + удаление/вставка/перестановка exits:
поток остаётся на прежнем разрешённом пути либо блокируется; на uplink нет
открытых VPN payload packets. Добавить аналогичный pure compiler regression.

### A03. Частично утраченная CA автоматически заменяется новой при startup

**Код:** `backend/kornode/main.py:44–55`,
`backend/kornode/services/certificates.py:79–116`.

Если отсутствует любой из `ca.key`/`ca.crt`, startup вызывает `init_ca()`.
Метод пишет новый ключ прямо в конечный `ca.key`, затем подписывает сертификат.
При наличии одного старого файла это не восстановление, а неявная смена identity.
Существующие dependent certificates/CRL не гарантированно перевыпускаются.

**Проверка:** fault injection после генерации ключа и до self-signing показывает
перезапись исходного ключа без rollback. Реальную CA не трогали.

**Исправление:** bootstrap разрешать только при полностью пустом PKI-state.
Частичное состояние — actionable startup error; rotation — отдельное явное
действие. Генерировать и проверять пары в staging, публиковать согласованно.

**Acceptance:** отдельно проверить missing-key, missing-cert, mismatch пары,
ошибку certtool на каждом шаге; никакой сохранившийся исходный материал не теряется.

### A04. `server.enabled` не управляет lifecycle уже зарегистрированного ocserv

**Код:** `backend/kornode/services/server.py:43–48,87–106`,
`templates/supervisor.conf.j2:35–48`,
`backend/kornode/api/routes_server.py:169–189`.

При сохранении `enabled=false` apply просто возвращает `None`; ocserv не
останавливается. Затем штатный `stop()` сам отказывает из-за disabled config.
При старте контейнера с выключенным server программа не зарегистрирована в
supervisord; перезапись файла при включении сама по себе её не регистрирует.

**Проверка:** mock supervisor RPC: disable не вызывает stop; enable с прежними
ocserv options вызывает HUP отсутствующей программы, что означает `BAD_NAME`.

**Исправление:** явные переходы enabled-state; остановка не должна запрещаться
desired disabled-state. Всегда регистрировать программу с управляемым autostart
либо применять корректный supervisor reread/update lifecycle.

**Acceptance:** container/RPC tests `true → false → true` и `false → true`:
фактический listener/process соответствует настройке, сессии при disable закрыты.

## P2 — безопасность и целостность конфигурации

### A05. Общая выдача config раскрывает inline private key / PKCS#12

**Код:** `backend/kornode/services/secrets.py:7–10,49–60`,
`backend/kornode/api/routes_config.py:48–51,263–270`.

`key_file_base64` и `cert_file_base64` не распознаются общей маскировкой; последнее
поле может содержать PKCS#12 с приватным ключом. Общий config/source API и safe
CLI dump выдают материал, хотя профильный upstream endpoint отдельно его скрывает.
Проверено на синтетических значениях. Требуется admin auth; это нарушение
write-only/redaction-контракта, не анонимное раскрытие.

**Исправление/тест:** централизованная классификация полей как секретных;
проверить `model_dump_safe`, config/source API, CLI stdout, errors и корректное
восстановление masked placeholders. Не ограничиваться regex на именах password/token.

### A06. Validation error возвращает разрешённый env-секрет

**Код:** `backend/kornode/api/routes_config.py:220–227`,
`backend/kornode/api/app.py:120–122`.

После secret resolution Pydantic видит открытые значения. `str(ValidationError)`
содержит `input_value`, а handler возвращает его клиенту. Проверка source/validate
с невалидным профилем и `${SECRET:AUDIT_SECRET}` вернула синтетическое значение
из env, которого не было в теле запроса. Endpoint административный.

**Исправление/тест:** структурированные ошибки без `input` и потенциально
секретного `ctx`; не сериализовать исключение целиком. Во всех config-validation
responses/stdout/logs проверить отсутствие resolved secrets.

### A07. YAML reorder переносит секреты между объектами

**Код:** `backend/kornode/api/routes_config.py:230–257`.

Masked values восстанавливаются в списках по индексу. Переставить A/B в masked
YAML и сохранить — B получает пароль A, A получает пароль B. Это также затрагивает
OIDC provider client secrets. Подтверждено вызовом restoration в памяти.

**Исправление/тест:** named collections сопоставлять по стабильному `name`/ID;
неоднозначные placeholders новых объектов отклонять. Проверить reorder,
удаление первого, вставку нового, rename и duplicate identities.

### A08. Смена admin credentials не отзывает уже выданные сессии

**Код:** `backend/kornode/api/auth.py:137–148`,
`backend/kornode/api/routes_config.py:118–133,182–198`.

TestClient подтвердил: старый пароль после смены не работает, новый работает,
но прежняя cookie продолжает давать доступ. Имеющий cookie может получить CSRF
через `/api/auth/me`. При default lifetime активная сессия может дожить до
абсолютного лимита — около 48 часов от создания.

**Исправление/тест:** общий auth revision/revoke-all при смене credentials и
значимых MFA-настроек, для всех writers. Проверить старую cookie после password
rotation, username change, MFA enable/disable.

### A09. Basic CSRF guard сравнивает hostname, а не полный origin

**Код:** `backend/kornode/api/auth.py:181–187`.

Сервер отклоняет другой hostname, но принимает `Origin: null` и другой
scheme/port того же hostname. Опасность возникает при автоматически повторяемых
браузером Basic credentials; bodyless mutating actions не защищены JSON preflight.
Server-side пропуск подтверждён; браузерный exploit end-to-end не запускался.

**Исправление/тест:** сравнивать scheme + hostname + effective port, учитывать
только доверенную proxy-конфигурацию; отклонять opaque/invalid origins. Сохранить
небраузерные запросы без Origin по явно принятой модели. Browser regression
для cached Basic, `null`, другого порта и downgrade scheme.

### A10. Subprocess log сохраняет секрет до маскировки результата

**Код:** `backend/kornode/services/command.py:202–215,236–252`.

`stdout/stderr` процесса напрямую привязаны к persistent file. Маскирование
применяется только к прочитанному обратно `CommandResult`. Synthetic child output
дал masked result, но открытое значение осталось в log. Это не доказательство,
что openconnect штатно печатает пароль; это отсутствие заявленного защитного
барьера, если subprocess напечатает чувствительные данные.

**Исправление/тест:** устойчивый logging sink, маскирующий до persistence,
включая background child после выхода parent. Проверять файл, а не только result;
учесть split chunks и права/rotation логов.

### A11. Settings-save теряет references и может удалить OIDC secret

**Код:** `backend/kornode/api/routes_upstream.py:165–185,213–219`,
`backend/kornode/api/routes_server.py:122–138,198–204`,
`backend/kornode/api/routes_identity.py:112–126`,
`frontend/src/api.ts:1043–1052`.

Два связанных round-trip дефекта:

1. Collections пересобираются из effective `model_dump()`: простой toggle
   upstream материализует `${SECRET:VPN_PASSWORD}` в открытый YAML. Аналогичный
   шаблон есть в OTP-save. После этого env rotation больше не меняет effective
   credential из-за приоритета YAML.
2. OIDC edit отправляет blank secret как null; backend заменяет provider моделью
   без сохранения прежнего `client_secret`, ломая confidential-client auth.

Проверено перехватом candidate patches с синтетическими секретами.

**Исправление/тест:** менять raw config по identity, сохраняя нетронутые references
и omitted fields. Различать «не менять», «заменить», «удалить». Проверить toggle
без materialization, последующую env rotation и OIDC edit без повторного ввода секрета.

### A12. Atomic replace не предотвращает lost update между writers

**Код:** `backend/kornode/api/routes_config.py:188–194`,
`backend/kornode/cli.py:149–155`, `backend/kornode/services/files.py:13–24`.

Read → merge → validate → write не защищён общей блокировкой/version check.
Два успешных PATCH разных полей могут прочитать одну версию, а последний write
потеряет чужое изменение. Воспроизведено двумя потоками с барьером в memory store.

**Исправление/тест:** межпроцессная блокировка для API/CLI/прочих writers;
optimistic version/ETag для source editor. Проверить сохранение обоих disjoint
patches и явный conflict для stale full-source save.

### A13. Ошибка render приходит после фактического сохранения

**Код:** `backend/kornode/api/routes_config.py:127–133,188–197`.

YAML уже заменён и `app.state.config` обновлён до генерации runtime files.
При render/write error клиент получает ошибку, но config изменён; generated state
может быть старым или частично новым. Подтверждено fault injection `OSError`.

**Исправление/тест:** предварительные validation/render/staging и определённая
commit/apply semantics. Если транзакция невозможна — явный `saved_but_not_applied`,
а не ложное «не сохранилось». Проверить сбой на каждом этапе, повтор и recovery.

### A14. Top-level config collections нельзя штатно задать через env

**Код:** `backend/kornode/config/env.py:129–153`.

Parser безусловно пропускает ключи без `__`. Поэтому `KORNODE_EGRESS`,
`KORNODE_SOURCES`, целиком `KORNODE_SETS` игнорируются. Индексный список parser
также не строит. Это нарушает требование env coverage для всех config fields.
Например, `KORNODE_EGRESS='[]'` не заменяет default policy.

**Исправление/тест:** поддерживать JSON-значения известных top-level schema keys,
не превращая arbitrary secret-env names в config. Явный пустой egress обязан
заменять default; добавить schema-driven env coverage tests.

### A15. CLI-save и loader валидируют разные effective configurations

**Код:** `backend/kornode/cli.py:161–167`,
`backend/kornode/config/loader.py:65–77`.

CLI candidate validation не передаёт provenance `explicit_paths`. При sparse YAML
с `node.id: 7`, `internal_dns.listen: 10.100.7.1` и omitted server network обычный
loader выводит правильный `10.100.7.0/24`, а CLI validation считает default network
явно заданным и отвергает конфигурацию. Подтверждено в памяти.

**Исправление/тест:** единый loader/candidate-validation pipeline с одинаковым
context; load → unrelated CLI patch → reload для non-default node ID и env values.

## P2 — runtime, redesign и GUI

### A16. Обещанный active alias не реализован, switch не меняет dataplane

**Код:** `backend/kornode/services/upstream.py:376–387`,
`backend/kornode/services/netinputs.py:97–115`,
`frontend/src/app/hooks/useUpstream.ts:177–191`,
`docs/spec/10-migration.md:32`.

UI/docstring обещают re-point traffic, но switch меняет marker; compiler facts
не зависят от него. Спецификация обещает `upstream:active`, однако такой target
даёт `unknown upstream 'active'`. Подтверждено synthetic compiler/provider test.

**Важно:** именованный `upstream:primary` должен оставаться pinned к primary;
его неизменность сама по себе корректна, это не основание менять все rules.

**Исправление/тест:** реализовать active alias и согласованный failover либо
убрать вводящие в заблуждение controls/обещания. Проверять конечный DesiredState,
а не только marker и вызов mock converge; pinned rules должны остаться прежними.

### A17. Upstream disable/disconnect semantics не согласованы с новой policy

**Код:** `backend/kornode/services/netinputs.py:107–115`,
`backend/kornode/services/upstream.py:695–713,854–869`,
`docs/spec/10-migration.md:21`.

External-interface disconnect сообщает «routing deactivated», хотя поднятый
интерфейс продолжает давать тот же desired route. Глобальное `upstream.enabled=false`
убирает profiles из facts, но сохранённые egress references вызывают `PolicyError`.
Этот конфиг принимается моделью/UI, хотя migration table объявляет старое значение
removed. Подтверждено mock/compiler checks.

**Ограничение:** profile enabled описан и как watchdog/dial control; не утверждается,
что он обязан автоматически переписывать явно именованную policy. Сохранение
last-good kernel state при compilation error — предусмотренная failure policy.

**Исправление/тест:** разделить dial lifecycle, availability и policy removal;
дать точные тексты действий. Недопустимый global-disable отклонять до commit
или представлять известный, но unavailable target. Проверить реальную policy и
процессы после каждого перехода, а не строку ответа.

### A18. Reconcile не замечает потерю одной owned NAT table

**Код:** `backend/kornode/net/kernel.py:201–228`,
`backend/kornode/net/diff.py:160–178`.

Schema hash читается из `inet kornode`. Если эта таблица и sets сохранены, но
`ip kornode_nat` отсутствует, ошибка её чтения игнорируется и plan может быть
пустым. Подтверждено synthetic nft JSON с настоящим непустым desired state.

Полный flush восстанавливается, поскольку исчезнет и schema comment. Находка
касается partial drift; ownership/single-writer снижает вероятность. Не заявляется,
что произвольный rule-by-rule drift detection уже обещан реализацией.

**Исправление/тест:** целостность всех owned tables должна участвовать в observed
state/hash validity; mock adapter и netlab test на удаление только NAT table.

### A19. `upstream connect --dry-run` меняет generated/secrets files

**Код:** `backend/kornode/services/upstream.py:403–451,512–523,603–609`.

До dry-run runner вызывается builder, материализующий cert/key, secret-bearing
openconnect config и vpnc-script. Temp-directory repro показал замену существующего
P12 и появление файлов. Опасного сетевого изменения не выполнялось.

**Исправление/тест:** pure dial plan отдельно от materialization. Dry-run на
существующей и read-only configuration не должен менять содержимое/metadata
generated и secrets directories или требовать запись для выдачи плана.

### A20. VLAN/interface names с точкой ломают sysctl paths

**Код:** `backend/kornode/net/kernel.py:98–99,191–199,294–297`,
`backend/kornode/net/compile.py:526–535`.

`net.ipv4.conf.eth0.100.rp_filter` разбивается в `.../eth0/100/rp_filter`
вместо `.../eth0.100/rp_filter`. Имена с точкой моделью разрешены. Fake procfs
read/write подтвердил неверный путь и `FileNotFoundError`; convergence может
завершиться ошибкой до dial/startup.

**Исправление/тест:** структурированный sysctl path с отдельным interface segment;
read/write round-trip для `eth0.100` и обычного interface, без реального `/proc/sys`.

### A21. Host DNS redirect не учитывает фактическую readiness dnsmasq

**Код:** `backend/kornode/services/host_dns.py:82–101,152–177`.

`wanted()` проверяет config, а не работающий resolver. При failed bind/start или
supervisor FATAL guard продолжает удерживать host DNS на неработающем адресе.
Условие требует включённого host DNS management и соответствующих mounts;
реальный сбой DNS хоста не воспроизводился.

**Исправление/тест:** readiness до redirect; определённая fail-closed/fallback
политика при отказе, hysteresis и явный статус. Возврат исходного resolver должен
учитывать требования против DNS leak, а не безусловно открывать обход VPN.
Проверить enabled config + реально неработающий/mock failed resolver.

### A22. GUI превращает nullable group booleans в явные false

**Код:** `backend/kornode/config/models.py:781–785`,
`frontend/src/api.ts:179–190,1080–1084`,
`frontend/src/app/hooks/useIdentity.ts:44–55`,
`backend/kornode/renderers/ocserv.py:124–133`.

Backend различает inherit/null, true, false. GUI draft — только boolean с default
false. Создание группы без изменения этих controls записывает явные
`tunnel-all-dns=false`, `no-udp=false` вместо наследования; DNS override может
ослабить глобальную настройку. Разница rendered output проверена в памяти.

**Исправление/тест:** nullable typed draft и трёхпозиционный control
«inherit / enabled / disabled»; round-trip всех состояний. При inherit директива
в group config отсутствует.

### A25. Документация обещает env precedence выше YAML

**Код:** `docs/configuration.md:20–26`, `docs/architecture.md:29–30`;
реализация — `backend/kornode/config/loader.py:65–77`.

## Дополнительные рекомендации, не отдельные доказанные уязвимости

1. **DNS transient failure policy.** `DomainResolverService` превращает DNS errors
   в пустой set и при отсутствии TTL ждёт до 3600 секунд
   (`services/domain_resolver.py:111–130,174–204`). Это соответствует текущей
   `docs/spec/02-egress-and-sources.md:114–121`, поэтому не классифицировано как
   нарушение контракта. При явном local fallback новые соединения могут пойти
   напрямую. Рассмотреть last-known-good для timeout/SERVFAIL, короткий retry,
   отдельный авторитетный negative result; UI должен показывать этот tradeoff.
2. **Supply-chain reproducibility.** `Dockerfile:6–8,72–79` допускает build без
   проверки ocserv SHA; release workflow передаёт optional variable
   (`.github/workflows/release-image.yml:81–83`). Для release сделать hash
   обязательным, фиксировать image digests и Python dependency resolution,
   генерировать SBOM и сканировать итоговый image. CVE scan в этом аудите не проводился.
3. **Immutable release identifiers.** `Makefile:56–73` удаляет и пересоздаёт даже
   version tags; `release:98–103` делает `git add -A` и ограничивается backend test.
   Разделить immutable version tag и явно mutable floating tag; выпускать из
   reviewed clean tree после полного gate. Эти commands аудитом не выполнялись.
4. **Liveness vs readiness.** `healthcheck.py:9–16` может считать runtime здоровым
   по socket path или без server/web; web-mode проверяет `/healthz`, который
   возвращает статический OK (`api/app.py:147–149`). Добавить отдельный readiness
   signal для reconciler/process state и актуальности config; не делать все
   внешние upstream outages безусловным поводом перезапускать контейнер.

## План исправлений

### Шаг 1 — security и isolation gate

- A01: закрыть TOTP bypass; связать с session invalidation A08 и Origin A09.
- A02: спроектировать устойчивый mark allocation/migration и packet-level regression.

### Шаг 2 — единый config transaction service

CLI и API должны переиспользовать не только модели, но и всю операцию
**read raw → patch by identity → validate effective with provenance → stage → commit
→ apply/status**. Включить preservation secret references, locking/versioning,
structured redacted errors и однозначные partial-success semantics.
Это общий корень A07, A11–A15; не устранять их независимыми endpoint-specific hacks.

### Шаг 3 — завершить redesign contracts

Определить active alias и disable/disconnect meanings (A16/A17), целостность
owned tables (A18), чистый dry-run (A19), VLAN sysctl paths (A20), DNS readiness
(A21), nullable GUI semantics и field parity (A22/A23).

- Запустить обычные checks на поддерживаемом Python 3.12 и container test stages.

- Отдельно disposable-VM E2E: restart, failover/active alias, CA recovery, upgrades.
